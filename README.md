# WebApp-Final-Project

跨平台 AI 社群內容工作台。使用者寫下主題，系統產生文案與圖卡版面，本人看過之後，才能發到 Threads、X、Instagram、Telegram。

前端在 `frontend/`，用 React 與 Vite。目前所有資料都是瀏覽器裡的示範狀態，還沒有呼叫後端。後端要做的是把下面這條狀態線存進資料庫，並接上生成與發布。

## 怎麼看前端

```powershell
cd frontend
npm install
npm run dev
```

瀏覽器打開 http://127.0.0.1:5173/ 。

## 頁面

| 頁面 | 使用者在做什麼 | 後端要配合的事 |
| --- | --- | --- |
| AI 創作工作台 | 四段流程：撰寫、編輯、審核、發布 | 生成文案、儲存草稿、送審、核准、發布 |
| 趨勢情報中心 | 看來源摘要，把一則來源帶進主題 | 抓取並保存 RSS 或網頁摘要 |
| 內容資料庫 | 依狀態找內容，並執行該狀態允許的動作 | 清單、篩選，以及下面的狀態規則 |
| 發文排程日曆 | 看尚未發出的排程，可以取消 | 依時間列出已排程，取消後改回已核准 |
| 內容審核 | 只列出待審核的內容 | 待審核清單；核准只在這裡發生一次 |
| 品牌版型中心 | 品牌名稱、預設語氣、四種圖卡配色 | 記住使用者的品牌設定 |
| 偏好與安全設定 | 語氣、受眾、已勾選平台、敏感詞、生成回饋 | 保存設定；發布前用敏感詞檢查 |

工作台的四段不能跳著做：

1. **撰寫**：主題、語氣、受眾。可以生成一則初稿，或一次生成 2 到 6 則系列。右邊只預覽，不能改版面。
2. **編輯**：改標題與內文、換說法、拖曳圖卡上的圖和文字、調整配色與字級。可以存成草稿，或送交審核。
3. **審核**：內容鎖定。使用者勾選「已讀過全文」和「有使用權利」之後才能核准。要改字必須退回草稿。
4. **發布**：只有已核准進得來。可以現在發布，或排一個未來的時間。

## 一則內容的狀態

這是後端最需要守住的規則。每一則內容同一時間只有一個狀態。

```text
草稿 → 待審核 → 已核准 → 已排程
                      ↘ 已發布
```

| 狀態 | 可以做 | 不可以做 |
| --- | --- | --- |
| 草稿 | 繼續編輯、覆蓋儲存、刪除、送交審核 | 核准、發布 |
| 待審核 | 核准、退回成草稿 | 直接改內容、刪除、發布 |
| 已核准 | 直接發布、排程發布、退回成草稿 | 直接改內容、刪除、再核准一次 |
| 已排程 | 取消排程（回到已核准） | 刪除、直接改內容 |
| 已發布 | 只保留紀錄 | 刪除、修改、再發布 |

送交審核只會把草稿改成待審核，不會自動核准。核准必須由人在審核步驟完成。伺服器收到發布請求時，若狀態不是已核准，要直接拒絕。

取消排程不是刪除。它把已排程改回已核准，並清掉排程時間。

## 一則內容要存的欄位

| 欄位 | 說明 |
| --- | --- |
| `id` | 內容編號 |
| `title` | 圖卡標題 |
| `content` | 貼文內文 |
| `prompt` | 產生這則時用的主題 |
| `tone` | 專業分析、輕鬆分享、討論互動 |
| `audience` | 受眾 |
| `status` | 草稿、待審核、已核准、已排程、已發布 |
| `style` | 四種配色的編號，0 到 3 |
| `font` | 標題字級 |
| `layout` | 圖形與文字的位置，各有 `x`、`y`，範圍大約 14 到 86 |
| `destinations` | 這則要發去的平台 |
| `when` | 排程或發布時間。現在發布可記成當下時間 |
| `sourceIds` | 撰寫時參考了哪些情報 |

`layout` 範例：

```json
{ "image": { "x": 50, "y": 30 }, "text": { "x": 50, "y": 72 } }
```

圖卡目前由前端用配色和座標畫出來，後端先負責把這些欄位存好。不必先做真實圖片生成。

## 需要的 API

路徑可以調整，但能力和狀態規則要對得上前端。

### 內容

| 方法 | 路徑 | 做什麼 |
| --- | --- | --- |
| `GET` | `/posts` | 內容列表。可用 `status` 篩選 |
| `POST` | `/posts` | 建立或覆蓋一則草稿 |
| `GET` | `/posts/{id}` | 取得一則，含版面與排程資訊 |
| `PATCH` | `/posts/{id}` | 更新標題、內文、版面。僅限草稿 |
| `DELETE` | `/posts/{id}` | 刪除。僅限草稿 |
| `POST` | `/posts/{id}/submit` | 草稿改為待審核 |
| `POST` | `/posts/{id}/approve` | 待審核改為已核准。請求裡要有兩個確認都為真 |
| `POST` | `/posts/{id}/return` | 待審核或已核准退回草稿 |
| `POST` | `/posts/{id}/publish` | 已核准立刻發布到 `destinations` |
| `POST` | `/posts/{id}/schedule` | 已核准改為已排程。時間必須在未來 |
| `POST` | `/posts/{id}/cancel-schedule` | 已排程改回已核准 |

核准請求：

```json
{ "readConfirmed": true, "rightsConfirmed": true }
```

排程請求：

```json
{ "when": "2026-10-21T09:00:00+08:00", "destinations": ["Threads", "Instagram"] }
```

`GET /posts?status=已排程` 就是日曆的資料來源。

### 生成

| 方法 | 路徑 | 做什麼 |
| --- | --- | --- |
| `POST` | `/generate` | 依主題、語氣、受眾產生一則標題和內文 |
| `POST` | `/generate/series` | 一次產生 2 到 6 則，每則都存成獨立草稿 |
| `POST` | `/posts/{id}/rewrite` | 沿用同一主題重寫。`mode` 為 `short`、`friendly` 或 `new` |
| `POST` | `/posts/{id}/local-edit` | 依照一句指示，只調標題、配色或字級，不重寫全文 |

產生初稿的請求：

```json
{
  "prompt": "整理近期 AI 產品商業化趨勢",
  "tone": "專業分析",
  "audience": "創業者與科技從業者",
  "sourceIds": []
}
```

系列請求再加上 `"count": 3`。回傳的每一則都要有自己的 `id`，前端會讓使用者先預覽再挑一則進編輯。

各平台的文字長短可以先由前端處理：X 截到約 240 字，Instagram 加一段開頭。若後端發布前要再格式化一次，請沿用同樣規則，不要另寫一套文案。

### 情報、設定、安全

| 方法 | 路徑 | 做什麼 |
| --- | --- | --- |
| `GET` | `/sources` | 情報列表：標題、類型、出處、日期、摘要 |
| `POST` | `/sources` | 新增一個網址或 RSS。後端抓標題與摘要後存起來 |
| `GET` | `/settings` | 讀取品牌名稱、預設語氣、受眾、敏感詞 |
| `PUT` | `/settings` | 更新上述設定 |
| `GET` | `/accounts` | 各平台是否已連接 |
| `POST` | `/accounts/{platform}/connect` | 開始連接該平台帳號 |
| `POST` | `/feedback` | 記下使用者對這則生成結果是喜歡、普通或不喜歡 |
| `POST` | `/safety/scan` | 檢查標題和內文是否含敏感詞，或「保證賺錢」這類絕對說法 |

敏感詞預設包含「未公開產品」「內部代號」「機密客戶」，使用者也能自行增減。發布和排程之前都要再查一次；有敏感詞就拒絕，並在回應裡列出偵測到的詞。

## 建議先做的順序

1. 內容的儲存、列表，以及上面的狀態轉換。
2. `/generate` 和 `/generate/series`，先回傳可用的標題與內文。
3. 敏感詞檢查，並在發布接口擋下未核准或含敏感詞的請求。
4. 情報來源的抓取與儲存。
5. 真正呼叫 Threads、X、Instagram、Telegram。這段可以最後做；在那之前，發布接口仍要完成狀態變更，並標明結果是示範發送還是正式發送。
